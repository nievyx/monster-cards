## Why trim the package?

Files required to develop or showcase the project need not be downloaded by every visitor. In particular, local Linux Pygame libraries inside `.venv/`, documentation, helper scripts, and a recorded gameplay video are not required by the browser game. Removing them from the **package** does not require deleting them from Git or the local project.

`gitignore` rules and Pygbag packaging filters solve different problems: `.gitignore` does not automatically exclude already present local files from the Pygbag archive.

## Proposed change 1 — Package filtering (not yet applied)

Add `pygbag.ini` at the project root, initially testing:

```ini
[DEPENDENCIES]
ignoredirs = [".venv", "docs", "assets", "scripts"]
ignorefiles = []
```

**Directory distinction:** Root `assets/` currently contains showcase media; runtime images and audio live under `src/assets/` and must remain packaged. Check this assumption again if the layout changes.

**Verify after rebuilding:** The console should list the new ignored directories. Inspect the new archive and play the browser game locally before publishing. Do **not** delete `.venv` or the video; only exclude them from packaging.

## Audio Conversion

During the Pygbag build on 24 October 2026, Pygbag
automatically converted WAV and MP3 files into OGG
using FFmpeg.

Generated files use names such as:
- fireball-pygbag.ogg
- icebolt-pygbag.ogg
- convert_audio_to_ogg-pygbag.py

These were generated by Pygbag, NOT by our manual
conversion script.

The existing scripts/convert_audio_to_ogg.py is a
separate utility for manually converting audio.

It was originally untested and has not been used
for this build.

Do not commit generated files without reviewing
whether they are needed.

### Pygbag Startup Screen — Confusing Click Area

**Date:** 24 October 2026  
**Status:** Working — low-priority UX issue  
**Environment:** Fedora Linux, Pygbag 0.9.3, Firefox

#### Observation

Pygbag displays a grey startup screen with a green message:

> Ready to start! Please click/touch page

The green rectangle resembles a clickable button, making it unclear where the user should click.

#### Investigation

- Clicking anywhere on the page successfully starts the game.
- Clicking the grey background works.
- The startup screen is provided by Pygbag, not Monster Cards.
- This is a usability issue, not a broken game hitbox.

#### Decision

No code changes required before the initial deployment.

**Future improvement:** Consider customising the startup screen to make the click-anywhere behaviour clearer.

#### Test Result

**PASS:** Browser startup confirmed working locally after restoring the original Pygbag packaging behaviour.
